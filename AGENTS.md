# Правила проекта

## Назначение и структура

Это калькулятор подбора IP-камер на Vue 3, TypeScript и Vite. Основные файлы:

- `src/App.vue` — композиция страницы.
- `src/components/CameraScenarioForm.vue` — ввод сценария и ограничений.
- `src/components/CameraRecommendation.vue` — расчёт рекомендуемых характеристик.
- `src/components/CameraResults.vue` — фильтрация, сортировка и карточки моделей.
- `src/composables/useCameraCalculator.ts` — расчёты и фильтры подбора.
- `src/utils/camera.ts` — форматирование, тип сенсора и определение исполнения.
- `src/types/camera.ts` — общие типы.
- `static/catalog.json` — каталог камер и их характеристики.

Сохраняй разделение UI и расчётной логики. Не размещай всю страницу и вычисления в одном компоненте.

## Правила данных каталога

- Не придумывай и не заполняй характеристики камер без подтверждённого источника. Неизвестные значения должны оставаться `null`.
- Для геометрии используй горизонтальное разрешение, диапазон фокусного расстояния и оптический формат сенсора. Физические `sensor_width_mm` и `sensor_height_mm` не требуются и не должны быть обязательными в данных; типовая ширина берётся из `estimatedSensorWidths` в `src/utils/camera.ts`. Нормализуй кавычки, пробелы и записи вроде `1/2.8 × 2`. Для сшитого панорамного канала множитель числа сенсоров учитывается в геометрии.
- Не используй `sensor_type` или мегапиксели матрицы как обязательные условия геометрического подбора. Если у камеры есть непустой `channels[]`, рассчитывай геометрию каждого канала отдельно и не подставляй вместо неё геометрические поля из общих `specs`. Применяй общие характеристики камеры — например, PoE, микрофон, IP и подсветку — к результатам её каналов.
- В карточке показывай оптический формат и название канала, если оно есть. Не показывай вычисленную типовую ширину сенсора как заводскую характеристику и не дублируй отдельной строкой фокусное расстояние, ширину сцены и PPM: эти значения уже выведены в карточке.
- Сохраняй дополнительные поля статуса и источника на правильном уровне записи каталога; не смешивай их с `specs`, если схема хранит их отдельно.
- Для обновления данных Arselan используй `scripts/sync_arselan_pricelist.py`. По умолчанию скрипт скачивает актуальный XLSX с `https://arselan.ru/f/prc.xlsx` в локальный `data/prc.xlsx`, затем сопоставляет известные камеры по коду 1С или бренду/модели и обновляет цены, не меняя проверенные характеристики. `--input путь.xlsx` использует локальный файл, `--offline` — локальный `data/prc.xlsx` и запрещает все сетевые запросы.
- Локальный скрипт также содержит флаг `--refresh-white-led-data`, но это не изолированное обновление: он запускает основной проход синхронизации и может обновить цены из `data/prc.xlsx`. Перед использованием учитывай этот побочный эффект. Папка `scripts/` игнорируется Git, поэтому локальные изменения этого скрипта сами по себе не попадут в push.
- Новые позиции классифицируются по карточкам поставщика. Подтверждённые как IP-камеры добавляются в `static/catalog.json` с источником данных и статусом, требующим сверки с документацией производителя. Явно аналоговые позиции сохраняются в локальном `data/arselan_state.json` и при следующих запусках пропускаются без повторной загрузки. Неизвестный тип и сетевые ошибки не считать не-IP; сохранять в локальную очередь `data/arselan_unmatched_cameras.json`.
- XLSX-прайс, кэш HTML `data/arselan_pages/`, состояние и очередь локальные, игнорируются Git. Для первого получения карточек нужен доступ к сайту (например, запуск скрипта с VPN); скачанные HTML переиспользуются офлайн. `--offline` запрещает сетевые запросы, `--refresh-pages` заново проверяет страницы и классифицированные не-IP позиции, `--refresh-supplier-records` перепарсивает ранее автоматически добавленные записи по локальному HTML-кэшу, `--enrich-incomplete` дополняет пустые геометрические поля в существующем каталоге по сохранённым или загруженным карточкам, не перезаписывая известные значения.

## Логика подбора

- Порог PPM выбирается по `densityStandard`: `dori` сохраняет классические профили 25 / 62,5 / 125 / 250 PPM; `iec2025` использует уровни IEC 62676-4:2025 — 20 / 40 / 80 / 125 / 250 / 500 / 1500 PPM. Не переименовывай категории новой редакции в старые уровни DORI.
- Переключение шкалы сопоставляет текущий профиль по назначению; PPM может измениться. Отдельно сохраняй возможность задать пользовательский PPM.
- Калькулятор использует шкалы как ориентиры плотности изображения и не подтверждает полное соответствие IEC 62676-4:2025.
- Геометрический расчёт проверяет, пересекаются ли диапазон объектива камеры и диапазон фокусных расстояний, нужный для заданных PPM, дистанции и ширины сцены. Для `channels[]` выполняй эту проверку независимо на данных каждого канала; в результатах показывай, какой канал прошёл подбор.
- Для типовой ширины, выведенной из оптического формата, проверяй устойчивость результата при отклонении ±10%. Сам факт использования справочного соответствия не делает камеру условно подходящей: условный статус нужен, если крайние значения меняют результат. Не показывай типовую ширину как заводскую характеристику.
- Неизвестные характеристики, важные для выбранного ограничения, не должны выдаваться за подтверждённое соответствие. Если логика оставляет модель в выдаче при неизвестных данных, добавляй заметное предупреждение и условный статус.
- Освещение: в режиме слабого света камеры с известным `minimum_illumination_lux > 0.01` исключаются; неизвестное значение оставляется с предупреждением.
- Полная темнота: проверяй, покрывает ли `ir_range_m` заданную дистанцию. Если дальность ИК неизвестна, не утверждай, что покрытие подтверждено; показывай предупреждение.
- Белая LED-подсветка не влияет на результаты, пока `needWhiteLed` выключен. Если пользователь включил переключатель, оставляй только камеры с подтверждённой белой LED-подсветкой; неизвестные данные не считай наличием. В слабом свете и полной темноте подсветка может заменить соответствующее условие освещения, если её известная дальность покрывает дистанцию. При неизвестной дальности показывай предупреждение и условный статус.
- Уличная установка: известный `ip_rating` ниже 65 исключает модель; неизвестный рейтинг сопровождается предупреждением.
- WDR, PoE и встроенный микрофон — включаемые пользователем требования. Выключенные переключатели не влияют на выдачу. Включённое требование пропускает только модели, у которых соответствующая характеристика подтверждена как `true`.
- Сохраняй множественный фильтр бренда, выбор исполнения камеры, переключаемое направление сортировки и адаптивный перенос `result-controls`.

## Интерфейс и тексты

- Интерфейс и пользовательские пояснения пиши по-русски.
- Не добавляй hero-блок. В шапке и футере оставляй компактную атрибуцию «Разработка @alebarrd».
- На широком экране ограничивай ширину рабочей области, чтобы поля не растягивались на весь монитор; на узком экране элементы должны переноситься и оставаться удобными.
- Статус «Подходит» означает, что модель проходит проверяемые условия. Не присваивай «Условно подходит» только из-за справочного замечания, которое не влияет на подбор.
- Не утверждай, что расчёт гарантирует качество идентификации, распознавания или чтения номеров; эти сценарии требуют полевой проверки.

## Команды и стиль

- Используй настройки Prettier проекта и сохраняй форматирование Vue SFC.
- `npm run format` — отформатировать файлы проекта.
- `npm run format:check` — проверить форматирование.
- `npm run build` — проверить TypeScript и собрать production-версию.
- Запускай тесты только по запросу пользователя.
