# Правила проекта

## Назначение и структура

Это калькулятор подбора IP-камер на Vue 3, TypeScript и Vite. Основные файлы:

- `src/App.vue` — композиция страницы.
- `src/components/CameraScenarioForm.vue` — ввод сценария и ограничений.
- `src/components/CameraRecommendation.vue` — расчёт рекомендуемых характеристик.
- `src/components/CameraResults.vue` — фильтрация, сортировка и карточки моделей.
- `src/composables/useCameraCalculator.ts` — расчёты и фильтры подбора.
- `src/utils/camera.ts` — форматирование, тип сенсора и определение исполнения.
- `src/types/camera.ts` — общие типы.
- `static/catalog.json` — каталог камер и их характеристики.

Сохраняй разделение UI и расчётной логики. Не размещай всю страницу и вычисления в одном компоненте.

## Правила данных каталога

- Не придумывай и не заполняй характеристики камер без подтверждённого источника. Неизвестные значения должны оставаться `null`.
- Отличай подтверждённые характеристики от оценочных. В частности, формат сенсора не является точной шириной сенсора.
- Если ширина сенсора `sensor_width_mm` отсутствует, её можно оценить по `sensor_format` через `estimatedSensorWidths` в `src/utils/camera.ts`. В карточке явно показывай, что ширина оценочная, формат и источник — расчёт по формату.
- Не используй `sensor_type` или мегапиксели матрицы как обязательные условия геометрического подбора. Основные параметры расчёта — горизонтальное разрешение, определяемая ширина сенсора и диапазон фокусного расстояния.
- Сохраняй дополнительные поля статуса и источника на правильном уровне записи каталога; не смешивай их с `specs`, если схема хранит их отдельно.

## Логика подбора

- Порог PPM выбирается по `densityStandard`: `dori` сохраняет классические профили 25 / 62,5 / 125 / 250 PPM; `iec2025` использует уровни IEC 62676-4:2025 — 20 / 40 / 80 / 125 / 250 / 500 / 1500 PPM. Не переименовывай категории новой редакции в старые уровни DORI.
- Переключение шкалы сопоставляет текущий профиль по назначению; PPM может измениться. Отдельно сохраняй возможность задать пользовательский PPM.
- Калькулятор использует шкалы как ориентиры плотности изображения и не подтверждает полное соответствие IEC 62676-4:2025.
- Геометрический расчёт проверяет, пересекаются ли диапазон объектива камеры и диапазон фокусных расстояний, нужный для заданных PPM, дистанции и ширины сцены.
- Для оценочной ширины сенсора проверяй устойчивость результата при отклонении ±10%. Одна только оценка не делает камеру условно подходящей: условный статус нужен, если крайние значения оценки меняют результат подбора. Показывай точную ширину без пометки оценки, оценочную — с явной пометкой.
- Неизвестные характеристики, важные для выбранного ограничения, не должны выдаваться за подтверждённое соответствие. Если логика оставляет модель в выдаче при неизвестных данных, добавляй заметное предупреждение и условный статус.
- Освещение: в режиме слабого света камеры с известным `minimum_illumination_lux > 0.01` исключаются; неизвестное значение оставляется с предупреждением.
- Полная темнота: проверяй, покрывает ли `ir_range_m` заданную дистанцию. Если дальность ИК неизвестна, не утверждай, что покрытие подтверждено; показывай предупреждение.
- Белая LED-подсветка не влияет на результаты, пока `needWhiteLed` выключен. Если пользователь её включил, подтверждённый белый LED может дать альтернативу фильтру освещения: при слабом свете — пройти условие по люксам, в полной темноте — заменить ИК, когда дальность белого света покрывает дистанцию. Если наличие подтверждено, но дальность неизвестна, камера может остаться с условным статусом и предупреждением. Не делай наличие белого LED обязательным для остальных камер; неизвестные данные не считай наличием.
- Уличная установка: известный `ip_rating` ниже 65 исключает модель; неизвестный рейтинг сопровождается предупреждением.
- WDR, PoE и встроенный микрофон — включаемые пользователем требования. Выключенные переключатели не влияют на выдачу. Включённое требование пропускает только модели, у которых соответствующая характеристика подтверждена как `true`.
- Сохраняй множественный фильтр бренда, выбор исполнения камеры, переключаемое направление сортировки и адаптивный перенос `result-controls`.

## Интерфейс и тексты

- Интерфейс и пользовательские пояснения пиши по-русски.
- Не добавляй hero-блок. В шапке и футере оставляй компактную атрибуцию «Разработка @alebarrd».
- На широком экране ограничивай ширину рабочей области, чтобы поля не растягивались на весь монитор; на узком экране элементы должны переноситься и оставаться удобными.
- Статус «Подходит» означает, что модель проходит проверяемые условия. Не присваивай «Условно подходит» только из-за справочного замечания, которое не влияет на подбор.
- Не утверждай, что расчёт гарантирует качество идентификации, распознавания или чтения номеров; эти сценарии требуют полевой проверки.

## Команды и стиль

- Используй настройки Prettier проекта и сохраняй форматирование Vue SFC.
- `npm run format` — отформатировать файлы проекта.
- `npm run format:check` — проверить форматирование.
- `npm run build` — проверить TypeScript и собрать production-версию.
- Запускай тесты только по запросу пользователя.
